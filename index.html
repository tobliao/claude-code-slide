1. 三個關卡：選校 / 選系 / 選方向

選校

學校給你的是環境、人脈、資源。在台灣，國立 vs 私立、北部 vs 中南部，差別不只在排名，更在你會被誰圍繞。

  • 同學是誰？學長姐去了哪？
  • 有什麼產學合作或實習機會？
  • 離家近 vs 換城市，哪個對你更好？

選系

科系決定你每天會花 4 年看什麼科目。資訊類、電機類、設計類、管理類，每一條都有它的甜點與痛點。

  • 看必修、不要只看科系名稱。
  • 找學長姐聊天比看簡章更真實。
  • 跨領域不是壞事，是放大器。

選方向

方向比科系大、比學校重要。你願意花 5–10 年深耕的，是產業、議題、還是某種人？

  • 科技、設計、教育、製造、醫療？
  • 偏向 B2B 還是 B2C？
  • 偏研發、應用、銷售還是教學？
選擇沒有絕對對錯，只有你願不願意為它負責、並且有沒有準備好調整。第一份決定不會綁住你 10 年，但會決定你接下來 1–2 年怎麼累積。

3. 為什麼選台科？選校 vs 選系的真實取捨

當時我在想什麼

  • 技職體系：對動手實作有信心，但學科底子需要補。
  • 北部 vs 中部：選擇北上換環境，逼自己跳出舒適圈。
  • 電機與資工很接近：硬體、軟體、AI 應用之間，在大學端是相通的；當時兩個領域都已經能看到 AI 的苗頭，但都還沒明確爆發。
  • 校風：台科工程實作風氣強，學長姐多在科技業。
真心話：選校時，我不是只看排名，是看「我想被誰圍繞」。同學的天花板，往往就是你的天花板。

我在台科怎麼學習（不是背答案）

  1. 找對讀書圈：3–5 個人一起寫題、互相講解，遇到卡關不會自己悶。
  2. 專注學英文：每天讀一點英文文獻、看一段英文影片，把英文當主科練 — 後來這變成我最關鍵的放大器。
  3. 每堂課的「為什麼」：搞懂背後邏輯，不是只記公式。
  4. 把專題當武器：每學期做一個能講 5 分鐘的小作品。
給你的提問：你身邊有沒有 3–5 個會逼著你變更好的同學？如果沒有，怎麼找到？

4. 為什麼要出國？香港 vs 台灣

HKUST：開放、競爭、混合

  • 同學來自全球：印度、新加坡、中國、東歐都有。
  • 英文是基本款，思辨與表達是進階款。
  • 研究文化偏「先動手、再修正」，速度感很強。
  • 第一次發現：原來世界比想像中大很多。

跨領域嘗試：Fair Learning

  • 在 HKUST 同期做了 Fair Learning（公平學習）的研究，是一次跨領域試水。
  • 後來沒有把 ML 公平性走深，但學到的是「敢花時間在不熟的題目」。
  • 真正讓我成長的，是被迫和不同訓練背景的人合作。
出國的真正價值，不是英文變好或多一個學位，而是你會被迫重新定義自己。在沒有人認識你的地方，你才會看到「拿掉學校光環之後，你還剩什麼」。
伏筆：出國不一定要靠留學或自費。畢業後我去深圳工作的那一年，也是一種「以工作的形式出國」 — 下一頁就講這段。

5. 深圳 → 台北：選擇的四個維度

當時為什麼去深圳

  • 以工作的形式出國：剛畢業就直接到深圳富士康工業互聯網，不靠留學也能跨出去。
  • AI 落地的真實場域：用 Python 把 AI 與資料分析嵌入工廠端，幫產線做數位化、自動化。
  • 節奏與密度：996 是真的，但能短時間看到技術從 demo 走進量產。

為什麼後來想回台灣

  • 應用工程師的限制：在那邊我只是把現成的 AI 套到場域 — 那不是「對社會有獨特價值」的工程師。
  • 晶片產業重心：台灣 IC 設計、驗證、製造一條龍，能做更底層、更難被取代的事。
  • 家人與生活：永遠不該被忽略的維度。
我用四個維度幫每個工作打分：薪資 / 成長 / 風險 / 幸福。沒有完美的選項，只有當下「總分最高」的選項。
給你的工具：把選項列出來，每個維度打 1–5 分。不要憑感覺，用紙本逼自己看清楚。

6. 學習歷程的真心話：3 個常見誤解

三個常見誤解

  1. 越多越好：拼命塞 20 個證照、10 個競賽。
  2. 越華麗越好：做精美海報，但內容空洞。
  3. 越像範本越安全：句型一樣、結構一樣、結果一樣被忽略。
大學端真正想看的，不是你做了多少，而是你為什麼做、過程中發生什麼、你怎麼想。

三個正解

  1. 有脈絡：每件事和你的興趣／方向能連起來。
  2. 有反思：這次比上次學到什麼、下次會怎麼做。
  3. 可驗證：有作品、有 GitHub、有照片、有數據。
最強的學習歷程，是讀的人會想多認識你，不是只有「看完了」。
延伸閱讀（台灣）： 學習歷程檔案撰寫全攻略 — 從心態建立到結構設計

7. 學習歷程四步法：從題目到證據

寫的時候從第一欄到第四欄，讀的人也會自然跟著你的思路走。反思那一段，是把作業變成作品的分水嶺。

STEP 01
題目 為什麼是這個？解決誰的問題？越具體，後面越好寫。
STEP 02
過程 你做了什麼？用了什麼工具、做了哪些決策、改了幾次？
STEP 03
反思 學到什麼？下次會怎麼做？這是讀的人最想看的部分。
STEP 04
證據 GitHub 連結、截圖、Demo 影片、使用者回饋與數據。
範例：班級作業提醒小工具
題目同學常忘記繳交作業，想做一個提醒小工具讓大家不再被扣分。
過程用 Cursor + Claude 做第一版，找 3 位同學測試、改 5 次 UI、加上 LINE 通知按鈕。
反思「設計簡單」比「功能多」更難；下次想加上自動推播與行事曆同步。
證據GitHub 連結、Demo 影片、3 位同學回饋截圖、改版前後對比圖。

8. 給高三的選校選系心法：兩種訊號

外部訊號（市場在說什麼）

  • 產業趨勢：半導體、AI、綠能、健康科技、文創。
  • 公司用人：看 104、LinkedIn 上的職缺需求。
  • 學長姐去向：你想就讀的那個系，畢業生在哪裡？
  • 教授是誰：這幾年有沒有在做有趣的研究？
外部訊號告訴你：這條路有沒有人走、走得遠不遠。

內部訊號（你自己在說什麼）

  • 能持續做 100 小時的事：什麼事你不會嫌煩？
  • 願意忍受的痛點：每個方向都有低潮，你能撐得住哪一種？
  • 讓你忘記時間的場景：寫程式、畫圖、和人聊天、做實驗？
  • 金錢觀：你是要穩定還是高峰，還是兩者兼具？
外部訊號 × 內部訊號的交集，就是你最值得花 5–10 年深耕的方向。

1. AI 時代的職場：被替換還是被放大？

已經正在發生的事

教育部已將生成式 AI 納入數位學習推動方案，並提出像 TAICA 這類 AI 學習聯盟，把 AI 素養變成跨領域基本能力。
北科大自 2024 學年度起，超過 1,500 名大一新生需要修習 AI 相關課程；台灣大學、清大、陽明交大也陸續把生成式 AI 納入通識或必修。
  • 業界招聘普遍要求「會用 AI 工具的工程師」。
  • 連設計、行銷、教育職缺，也開始把 prompt 能力寫進 JD。

關鍵分水嶺

同一個職位，差別在於兩種人：

  • 被替換：把工作交給 AI 後，自己沒有額外價值可以提供。
  • 被放大：用 AI 當副手，把自己擅長的事做到 5 倍快、5 倍多、5 倍深。
不是 AI 取代人，是會用 AI 的人取代不會用 AI 的人。這句話不是為了嚇你，是為了告訴你：今天就可以開始。

2. 什麼是 Vibe Coding？

原始定義

Vibe Coding 一詞由 OpenAI 共同創辦人 Andrej Karpathy 在 2025 年 2 月提出：

「There's a new kind of coding I call vibe coding, where you fully give in to the vibes... and forget that the code even exists.」 — Andrej Karpathy

意思是：你不再逐行寫程式，而是用自然語言描述你要的東西，讓 AI 把程式寫出來，再用對話迭代修改。

傳統寫程式 vs Vibe Coding

面向傳統Vibe Coding
起手式背語法、查文件說清楚需求
核心能力記憶語法清晰描述
除錯自己 trace把錯誤丟給 AI 解釋
速度線性累積非線性放大
講者親身案例：副專案 Orion EEG 是一支 React + FastAPI 的 Android App（搭配 Muse 腦波耳機做香氛測試），完全用 Cursor 的 Vibe Coding 工作流獨立完成並上線。

3. 業界現場：三種人怎麼用 Vibe Coding

軟體工程師

用 Cursor + Claude 做重構、寫單元測試、解 bug。原本要花 2 天的功能，常常半天就能跑出第一版，剩下時間拿來想架構。

硬體驗證（講者本職）

晶片驗證寫的是 SystemVerilog／UVM。AI 可以協助產生 SVA assertion、覆蓋率分析、log 解讀，讓資深工程師花更多時間在架構決策。

新創 / 個人開發者

從想法到 MVP（最小可動產品）從以前 1–2 個月，現在常常 1 週內就能上線給人試用。試錯成本大幅下降。

現場示範：等下我會直接打開 Cursor，秀一段我用 Vibe Coding 做的 Orion EEG 香氛專案程式給你們看 — 從 prompt 到能跑的 React + FastAPI Android App。
不論你未來走哪條路，Vibe Coding 都是基本功。就像你不會說「我不需要會用搜尋引擎」一樣，AI 工具會在 3–5 年內變成水電一樣的存在。

4. Vibe Coding 心法：四句話框架

把這四句話講清楚

  1. 我是誰：我的角色、程度、需求背景。
  2. 我要做什麼：作品目標、要解決的問題。
  3. 我要什麼風格：版面、語氣、限制條件。
  4. 請怎麼輸出：完整 HTML？逐步教學？條列建議？
這比 CO-STAR、APE 這些花式框架都好記。問你自己這四個問題，AI 就知道怎麼幫你。

學生版 Prompt 範例

1. 工具一：Claude 註冊（5 分鐘搞定）

Step-by-step Setup

先有帳號，
才有第一句話。

Claude 是 Anthropic 推出的 AI 對話助手。免費版每天有一定額度，做學習用途、寫小專題完全夠用。

提醒：不要在對話裡丟身分證、信用卡、密碼。AI 對話內容可能被用於改善服務。
STEP 1
打開官網

到 claude.ai，按「Sign up」或「Continue with Google」。

STEP 2

STEP 3
同意條款 + 設定名字

填一個喜歡的稱呼，選擇「我是學生 / 學習用途」。

STEP 4

2. Claude 第一個 prompt：直接複製來用

逐段拆解

  • 第一段（我是誰）：告訴 Claude 你的程度與身分，回答會自動調整深度。
  • 第二段（我要做什麼）：把問題講具體，不要只說「幫我做網站」。
  • 第三段（風格）：講出顏色、語氣、限制條件。
  • 第四段（輸出）：明確指示「請給我完整 HTML 檔案」。
小撇步：請 Claude 用繁體中文回覆，並要求它列出可能的設計選項，再讓你挑，不要一次給死答案。

完整可貼 prompt

我是大甲高工資訊三甲的學生，剛考完統測。 我想做一個「英文單字卡 Web App」當作我的學習歷程作品。 功能需求： 1. 我貼上一段英文單字（中英對照） 2. 系統幫我產生可以翻面的卡片 3. 用箭頭或點擊切換下一張 4. 標記「已會 / 不會」並儲存到 localStorage 5. 手機與電腦都要好看 風格：深色背景、Apple 風乾淨設計、字級要大。 請直接輸出完整單一 HTML 檔案， 所有 CSS / JS 都寫在同一個檔案裡， 我可以直接打開瀏覽器測試。

3. 工具二：Cursor 介面導覽

Cursor 是什麼

Cursor 是一個內建 AI 的程式編輯器，外觀像 VS Code，但每一個地方都接上 AI。學生免費版可以使用 GPT、Claude 等模型。

  • 左側：檔案總管（你的專案結構）。
  • 中央：程式碼編輯器（會看到 AI 自動補全建議）。
  • 右側：Chat / Composer（和 AI 對話、生成多檔修改）。
  • 底部：Terminal（執行指令、開伺服器）。

三個必學快捷鍵

  • Cmd / Ctrl + L：開啟 Chat 面板，問問題。
  • Cmd / Ctrl + K：在程式碼裡直接叫 AI 改這一段。
  • Cmd / Ctrl + I：開啟 Composer / Agent，做大範圍修改。
小技巧：在 Chat 裡輸入 @ 就可以提到特定檔案、整個 Codebase、或網址，讓 AI 知道你在說什麼。

4. Cursor 操作步驟：從零到第一個成品

五個步驟，10 分鐘內就能跑出第一個能在瀏覽器打開的 HTML。

STEP 01
下載安裝

到 cursor.com 下載對應 OS 版本，登入帳號。

STEP 02
開新資料夾

桌面建一個 my_project，用 Cursor 開啟（File → Open Folder）。

STEP 03
Cmd+I 開 Composer

把剛剛的 prompt 貼進去，按送出，等 AI 生成 index.html。

STEP 04
檢視 + Apply

確認生成內容沒問題，按「Apply」讓檔案實際寫入資料夾。

STEP 05
打開瀏覽器

右鍵 index.html → Open with Browser，看你的第一個 Vibe Coding 作品。

如果第一次跑不起來不要慌：把錯誤訊息整段複製貼回 Chat 給 Cursor，請它修。AI 最擅長就是這個。

5. Cursor 進階：把它當成一位真正的副手

Agent Mode

讓 Cursor 自己跨多個檔案修改、執行指令、看 log、再修。適合在你已經有第一版以後，請它做大幅功能升級。

Rules

在 .cursor/rules/ 寫下你希望 AI 永遠遵守的規則（例：永遠用繁體中文、永遠用深色主題），AI 就不會每次都要重講一遍。

@Codebase

在 Chat 裡打 @Codebase，AI 會把整個專案當作上下文來回答。問「這個按鈕在哪裡定義的」、「這段邏輯為什麼這樣寫」都很好用。

最有效的學習方法：先讓 AI 做第一版，然後讓它一段一段解釋「為什麼這樣寫」。你會學得比自己 google 更快。

6. Vibe Coding 黃金組合：兩工具如何接力

① 在 Claude 想清楚

把模糊的想法變成清楚的需求。讓 Claude 幫你列功能清單、畫流程、想可能的版面。

  • 「我這個想法的 5 個功能會是什麼？」
  • 「給我 3 個版面方案，比較優缺點。」

② 到 Cursor 做出來

把 Claude 的需求清單複製貼到 Cursor Composer，讓 Cursor 直接生成檔案、修改檔案、執行測試。

  • 用 Cmd+I 跨檔案修改
  • 用 Terminal 跑開發伺服器

③ 自己驗證

跑起來、測試、改細節。最後一段一定是你的審美和判斷，不能完全外包。

  • 手機上能不能看？
  • 這真的「像我」嗎？
記住：Claude 是規劃師，Cursor 是執行者，你才是導演。三者缺一都不會做出讓你滿意的作品。

1. 怎麼切入題目：三個生活化方向

不要想著「做一個改變世界的專題」。先做一個解決你身邊小困擾的東西。越小越好。

① 生活困擾

  • 班級點名 / 出缺勤紀錄小工具
  • 社團活動報名單頁
  • 同學生日提醒、便當揪團
  • 學生會選舉投票頁
問自己：上週我為「什麼小事」感到不耐煩？那就是你的題目。

② 讀書 / 學習效率

  • 考前單字卡 / 公式卡產生器
  • 英文聽力短句循環練習
  • 錯題本：拍照上傳 + 分類
  • 番茄鐘 + 自動紀錄
高三準備統測時最痛的點是什麼？做出來，下一屆學弟妹會感激你。

③ 興趣 / 個人風格

  • 個人作品集（學習歷程用）
  • 追劇 / 動漫 / 遊戲評分清單
  • 運動紀錄器（跑步、重訓）
  • 音樂 Podcast 推薦頁
挑你下課還會聊的東西。這種題目的細節最容易做得有靈魂。

2. 選定題目前，先回答這 4 個問題

四個必答

  1. 你解決誰的問題？（自己、同學、學弟妹、家人？）
  2. 這個問題多痛？（每天遇到 / 偶爾遇到？讓人多煩？）
  3. 最小可動版本（MVP）長什麼樣？（90 分鐘做得完的版本）
  4. 哪段交給 AI？哪段你親自做？（程式 vs 內容判斷 vs 設計品味）

選題避坑指南

  • 避免：要連 LINE / Instagram API、要做後端伺服器、要做 App 上架。
  • 建議：單一 HTML 檔案就能跑、資料用 localStorage 存。
  • 建議：先做能動的版本，有時間再加功能。
如果你卡在選題，最快的解法是把上面 4 個問題打進 Claude，讓它幫你討論。

3. 分組規則：1–3 人一組

選一個適合自己的組合

  • 1 人：題目自由發揮，做出能跑的版本即可，重點是練手感。
  • 2 人：要有明確分工（一人想需求 + 內容、一人主寫 prompt + 改 code）。
  • 3 人：題目深度要更深 — 例如多頁面、多功能、有資料持久化（localStorage / JSON 檔），或結合兩個切入方向。
3 人組請在開工前先告訴助教題目，確認深度有達標。
分組沒有優劣，重點是每個人都實際參與一次完整的 Vibe Coding 流程。

AI 時代，我們可以怎麼跟它互動？

① 把 AI 當副手，不當答案

AI 給你的永遠是「一個版本」，不是「正確答案」。它是你的助理，不是你的老闆。最後拍板的是你。

② 提問力 > 記憶力

背誦的價值在下降，會問問題的價值在上升。問得清楚，AI 就能幫你；問得模糊，AI 也只能模糊。

③ 不能外包的事：判斷與責任

AI 寫的程式有 bug、生的內容會錯、給的建議會偏。判斷對錯 + 為結果負責，永遠是你的事。

給你最後一個畫面：未來會有很多人和 AI 一起工作。差別在於 — 有人讓 AI 取代自己的思考；有人讓 AI 放大自己的思考。你想當哪一種？
不論你之後讀什麼科系、走哪個產業：會用 AI、判斷 AI、和 AI 一起把事做出來，會是你接下來十年最划算的投資。
